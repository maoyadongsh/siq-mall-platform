# SIQ 前端高级视觉与交互升级计划

## Context

当前前端功能较完整，但视觉主要停留在基础卡片与表单堆叠：商城和运营共用拥挤页头，首页与商品详情缺少清晰视觉焦点，购物车、结算、订单的信息层级偏弱，H5 缺少稳定的一级导航与底部操作区，小程序存在较多内联样式。本次以 Apple 的精确网格、克制反馈和 Claude 官网的温暖留白、编辑式排版为方向，在保留暖白/深松绿品牌与全部业务规则的前提下，完成可感知、可复用的整体升级，而非单纯换色或增加装饰。

## 推荐方案

### 1. 建立统一但分场景的设计系统

- 在 `frontend/src/styles/variables.scss` 扩展基础色板、语义色、组件尺寸、圆角、阴影、层级与 120–200ms 动效 token；保留 `#174C43`、`#F7F6F2`、`#E8F0EB` 等既有品牌值，仅以低饱和陶土色作辅助装饰。
- 在 `frontend/src/styles/index.scss` 统一系统字体、标题字距与行高、金额等宽数字、按钮/输入/链接焦点、选择与禁用状态；补齐 `:focus-visible`、`prefers-reduced-motion`、全局加载/空态/错误样式。
- 商城采用大留白、轻边界和柔和层次；运营通过独立布局覆盖控件高度、表格密度和内容宽度，避免把营销式卡片带入后台。不引入字体、图标或动效依赖。

### 2. 分离商城与运营布局，完善 PC/H5 导航

- 重构 `frontend/src/layouts/DefaultLayout.vue`：消费者页头只保留品牌、首页、选购、领券、购物车及权限内账号/消息/运营入口，使用 64–72px 暖白吸顶导航和克制的激活态。
- H5 一级页增加首页、选购、购物车、我的底部导航；详情、结算等任务页隐藏一级导航，保留等高安全区占位，不出现双层底栏。
- 新增 `frontend/src/layouts/OpsLayout.vue`，集中现有权限导航，形成约 224px 侧栏、顶部页面信息区和自适应内容区；窄屏保留规范要求的查询与单笔履约能力。
- 调整 `frontend/src/router/index.ts` 的路由分组及展示元信息，保持所有路径、权限 meta、守卫、懒加载与跳转行为不变。

### 3. 深化商城首屏与商品浏览体验

- `HomeView.vue` + `content.css`：首屏改为温暖浅色、编辑式大标题、明确价值文案与一体化搜索；分类改为轻量胶囊，公告、CMS Banner/楼层、服务说明形成有节奏的区块。继续复用 `ContentBlocks` 和真实 CMS/商品数据，无内容时保留可售商品兜底。
- `ProductGrid.vue`：统一真实商品图的 4:3 比例、标题/价格层级、整卡链接、hover/focus 和加载失败表现；桌面多列、紧凑双列、移动单列，不使用占位图或虚构销量。
- `CatalogList.vue` + `catalog.css`：消费者列表复用 `ProductGrid`，筛选区保留 URL 查询参数、清空与分页逻辑；桌面排列紧凑，移动端分组换行。商品管理分支改为高密度表格，不再套用商城商品卡。
- `ProductDetail.vue`：桌面形成媒体与购买信息双栏，规格、库存、价格、数量和唯一加购主动作集中呈现；移动端使用带安全区的底部操作栏。保留现有加购、游客购物车、评价与异常处理，不新增“立即购买”。
- 图片继续使用商品 `cover_url` 与 CMS 媒体；如确需新增 Web 图片，仅使用规定的 `text_to_image` URL 生成真实内容，并补齐 alt、尺寸和懒加载策略。

### 4. 重构交易与订单的信息层级，不触碰业务算法

- `CartView.vue`：商品行、数量/选择/移除操作与结算摘要分区，突出失效原因和待合并/待找回状态；仅展示服务端数据，不在前端重算最终应付。
- `CheckoutView.vue`：按地址、优惠券、商品明细、金额与提交组织内容；桌面摘要吸顶，移动提交栏固定并预留安全区。原样保留报价过期、价格变化、优惠券不可用、重复提交保护和找回原订单流程。
- `OrderList.vue` / `OrderDetail.vue`：统一语义状态标签、订单号/金额排版、操作优先级和订单事件时间线；`allowed_actions`、模拟支付说明、二次确认、发货 version 与结果未知恢复逻辑不变。
- 失败继续保留输入和已有内容，加载、空态、失败、禁用与成功反馈采用一致样式，不增加只镜像 DOM 的样式单测。

### 5. 运营后台提效而非“商城化”

- `OpsDashboard.vue` 使用真实待办构成紧凑任务总览，不编造销售额、增长率或图表。
- 商品管理复用 `CatalogList.vue` 的 `manage` 分支实现紧凑表格；订单列表/详情延续上述组件但由 `.ops-layout` 控制密度、局部横滚和关键操作可达性。
- 其余审核、营销、CMS、客服、权限页面先继承 OpsLayout、全局 token 与 Element Plus 主色/焦点变量，不做全量重写，不改变表单和权限行为。

### 6. 原生小程序同步同一品牌语言

- 在 `mini/app.wxss` 建立与 Web 对应的页面标题、区块、状态、商品行、底部操作栏等公共类，统一 20rpx 左右卡片圆角、88rpx 触控目标和金额排版。
- 清理 `pages/index/index.wxml`、`pages/products/products.wxml`、`pages/product/product.wxml`、`pages/cart/cart.wxml`、`pages/checkout/checkout.wxml`、`pages/orders/orders.wxml`、`pages/order-detail/order-detail.wxml` 的主要内联样式，优化首屏、规格选择、结算明细与状态层级。
- `mini/app.json` 原生导航改为暖白底、深色文字，保留首页/购物车/我的三个 tab；商品与结算增加底部操作栏等高占位。只改 WXML/WXSS/导航配色，不改 JS、存储、分享、报价和幂等逻辑。

### 7. 验收记录

按现有任务映射更新 `docs/02-iteration-plan.md` 与 `docs/11-readiness-and-acceptance.md` 的实现和自动验证证据；“自动验证通过”与“人工验收通过”分开登记，不将浏览器模拟写成微信开发者工具或真机结果。

## 实施顺序

设计 token 与双布局壳 → 首页和共享商品卡 → 商品列表/详情 → 购物车/结算/订单 → 运营代表页 → 小程序 → 浏览器走查与回归。每阶段复用现有 API、类型和状态逻辑，控制在上述文件及必要测试选择器更新内，不改后端、OpenAPI、Pinia 会话或请求层。

## 验证

1. 在 `frontend` 执行 `npm run lint`、`npm run typecheck`、`npm test`、`npm run build`。
2. 执行 `npm --prefix mini test` 与 `node --test qa/acceptance/mini-boundaries.cjs`；如 Web 流程需要真实后端联测，再按现有隔离环境运行 `backend/.venv/Scripts/python.exe qa/windows/smoke.py`，不命中业务生产库。
3. 浏览器检查 320/375/390/430/768/1440 宽度，走查首页→列表→详情→购物车→结算→订单，以及运营工作台→商品管理→订单履约；验证无横向溢出、底部栏不遮内容、图片正常解码、键盘焦点清晰、减少动态效果生效、失败保留输入。
4. 分别记录自动测试、Windows 浏览器联测与人工签收结果；微信开发者工具、体验版、真机和性能指标不预设通过。
