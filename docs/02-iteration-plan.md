# 优选商城迭代计划

版本 v2.0｜2026-11-06｜依据《01-architecture.md》v2.0｜AI 修订稿，待人工审核。
本版替代旧排期；T 编号按新迭代定义。旧验收文档保留为历史记录，不把旧“已验收”自动移植到新版。

## 1. 交付规则

Windows 11 开发，Ubuntu 24.04 原生部署，无 Docker。每次交付都是可部署的累积版本；独立部署不表示切割为独立微服务。未完成功能不暴露路由和按钮。每个迭代须提供代码/迁移、接口契约、测试报告、部署与回滚步骤、验收登记。

状态：待开始 → 开发中 → 自动验证通过 → 待人工验收 → 已验收；失败则整改。只有人工填写验收人、日期和结论才能“已验收”。单项完成立即登记，迭代验收另登记，不以 AI 的文字结论代替签字。

每项任务的验收清单 = 下表该行标准 + 公共清单 G1–G6，逐项记录“通过/失败/不适用（原因）”，不得只填“完成”。

- G1：对应正常路径和参数边界通过，有测试名称/命令/输出。
- G2：登录与权限适用时验证未认证、越权、角色隔离。
- G3：迁移、接口、字段与架构一致，旧功能回归通过。
- G4：页面具备加载、空、错误、成功状态；375/768/1440px 与键盘操作验证。
- G5：在累积版本中能独立部署、使用真实依赖冒烟；记录版本/配置/环境与回滚结果。
- G6：人工审核无阻断项，登记负责人、证据位置、日期、结论。

## 7. I05 购物车与试算

| 任务 | 内容 / 产物 | 验收清单与标准 |

| T05-01 | 购物车写操作 | user+sku唯一；加购/改量/删除/选中；1–99边界；相同幂等键不重复累加 |

## 8. I06 订单、模拟支付与履约

| 任务 | 内容 / 产物 | 验收清单与标准 |
| --- | --- | --- |
| T06-01 | 订单/明细/地址快照 | 修改商品或地址后历史订单不变；金额字符串精确；订单号唯一 |
| T06-02 | 幂等与事务扣库存 | MariaDB并发50抢10件恰10成功；同键同参数一单；同键异参数409；失败事务不残留扣减 |
| T06-03 | 支付模拟和取消 | 只操作本人支付单；金额不符拒绝；重复支付不重复记账；取消后支付失败；生产默认关闭模拟 |
| T06-04 | 超时关单与Outbox | expires_at后扫描≤90秒处理（正常worker下）；任务重复不双补库存；提交后worker宕机能补投 |
| T06-05 | 运营发货与用户收货 | paid→shipped→completed；非运营发货403；只有本人确认收货；非法状态转移拒绝 |
| T06-06 | 订单和交易记录页面 | 结算→模拟支付→结果→订单时间线走通；用户中心复用订单数据；异常可重试不多单 |

独立部署验证：购买一单完成收货、另一下单取消、第三单超时；三个库存流水与订单状态一致。该阶段只有演示支付，不对外经营收款。

## 11. I09 通知

| 任务 | 内容 / 产物 | 验收清单与标准 |
| --- | --- | --- |
| T09-01 | 消息与模板 | 接收人索引；模板变量缺失显式失败；不直接暴露内部异常或收货信息 |
| T09-02 | Outbox消费者 | event+consumer唯一；重复事件一条消息；worker恢复后补投；正常链路10秒内到达 |
| T09-03 | 查询与已读 | 用户隔离；重复标已读不减成负数；全部已读与新消息竞争不丢未读 |
| T09-04 | 消息中心 | 分类、未读角标、业务跳转、分页；无权限关联资源不可打开 |

独立部署验证：支付→发货→收货分别产生消息；取消用另一条待支付订单，不测试非法的“支付后直接取消”。CMS公告联动在I10追加，不反向依赖I10。
