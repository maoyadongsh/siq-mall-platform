## 1. 交付规则

Windows 11 开发，Ubuntu 24.04 原生部署，无 Docker。每次交付都是可部署的累积版本；独立部署不表示切割为独立微服务。未完成功能不暴露路由和按钮。每个迭代须提供代码/迁移、接口契约、测试报告、部署与回滚步骤、验收登记。

状态：待开始 → 开发中 → 自动验证通过 → 待人工验收 → 已验收；失败则整改。只有人工填写验收人、日期和结论才能“已验收”。单项完成立即登记，迭代验收另登记，不以 AI 的文字结论代替签字。

每项任务的验收清单 = 下表该行标准 + 公共清单 G1–G6，逐项记录“通过/失败/不适用（原因）”，不得只填“完成”。

- G1：对应正常路径和参数边界通过，有测试名称/命令/输出。
- G2：登录与权限适用时验证未认证、越权、角色隔离。
- G3：迁移、接口、字段与架构一致，旧功能回归通过。
- G4：页面具备加载、空、错误、成功状态；PC 768/1440px、移动H5 320/375/390/430px；小程序另验iOS/Android真机、软键盘、安全区、原生导航和前后台恢复。浏览器原型通过不能替代小程序验收。
- G5：在累积版本中能独立部署、使用真实依赖冒烟；记录版本/配置/环境与回滚结果。
- G6：人工审核无阻断项，登记负责人、证据位置、日期、结论。
