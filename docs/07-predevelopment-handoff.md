## 2. 本轮收敛结果

| 决策 | 本版设计基线 | 变更影响 |
| --- | --- | --- |
| 产品 | 单商家、人民币、实物商品、一个订单一次发货 | 多商户/拆单/售后另立设计 |
| 客户端 | PC商城、移动H5、买家小程序，共用后端；运营后台PC主用 | 小程序不是缩小的网页，也不承载完整运营后台 |
| 首版范围 | F01–F11全部纳入V1，按I01–I11逐步可部署 | 尚未进入对应迭代的功能隐藏入口，不放无效按钮 |
| 视觉 | 暖白、深松绿、低饱和辅助色；优先信息层次与可操作性 | 不以大面积金色、低对比灰字或装饰动效替代品质 |
| 用户 | 保留auth.User，一对一Profile；外部身份显式关联 | 不重建现有库、不直接替换AUTH_USER_MODEL |
| 交易 | 后端试算、数据库事务、订单快照、幂等与Outbox | Redis或前端状态不能决定交易成功 |
| 支付 | 仅隔离演示环境模拟；常规生产默认关闭 | 真实支付和退款不计入本轮完成度 |
| 部署 | Windows 11开发；Ubuntu 24.04原生部署 | 无Docker/Kubernetes |

本版补齐此前未形成详细交互的优惠券运营、CMS发布、评价审核、消息中心和客服工作台：页面、字段、权限、状态和验收均有文字规格。已有交互原型用于理解流程，不是生产实现；新增模块尚无同等深度的可点击高保真原型，需在对应UI任务中按规格制作并人工评审。

## 3. 已有原型与代码证据的边界

已有独立HTML原型：交易闭环V2、运营商品/履约V3、移动H5/小程序模拟V4。它们位于用户本机可视化目录，未纳入本仓库交付依赖；08/09/10给出可独立阅读的设计语义。原型示例数据不与真实数据库同步，原型中的平台授权不是微信实际能力测试。

[05验证报告](05-review-validation-2026-11-06.md)仅作为历史证据。本轮I01已修复测试语法问题、复核认证迁移草稿并消除实际OpenAPI漂移，可执行补验结果见11§8。I01仍待Ubuntu预发和人工签字；I02草稿未接入，I03–I11尚未实现。

## 4. 开工判断

设计包已具备评审、拆任务和开展基础框架补验的条件。完成11中的P01–P04后，可按已授权范围进入身份/权限和用户资料开发；小程序的真实平台实现须先完成X01能力核验。平台账号未到位只阻塞相应适配与发布，不阻塞共用领域模型和Web业务。

本轮不冒充完成以下事项：人工签字、真实微信权限核验、Ubuntu部署、真机验收、数据库并发测试、正式商业发布。它们已经登记负责人角色、验证标准和影响范围。用户后续明确要求实现时即可执行对应任务，不需为每个常规文件编辑重新请求许可。
