## 1. 目标

围绕报价、下单、支付、取消、履约和事件投递，验证系统在响应丢失、重复操作、状态竞争与进程异常下仍能恢复且保持唯一事实。优先复用真实服务、临时 MariaDB/Redis 和浏览器故障注入；发现缺陷才做最小修复，不用新增功能或虚构失败制造迭代工作量。

## 2. 本轮范围

1. 报价过期、价格变化、地址/优惠券切换及迟到响应的代次隔离。
2. 下单结果未知时按原购买意图、报价和幂等键找回；同键异参和重复提交不得产生第二单。
3. 模拟支付失败重试、超时查询原支付单、支付与取消/超时关单竞争。
4. 库存与优惠券预占、核销、释放的唯一性，发货版本冲突及合法订单状态机。
5. Outbox 消费回执、重复投递、worker 异常后的单次释放和重启补扫。
6. 补充缺少的自动回归，更新 plan、handoff、验收台账和证据索引。

## 3. 不在本轮范围

- 不接入真实支付、退款、对账、真实物流或支付回调。
- 不改变公开 API、金额算法、订单状态和权限语义，除非已确认缺陷且完成契约同步。
- 不清理或重置现有业务数据库，不使用 Redis 代替数据库事实约束。
- 不声称完成微信开发者工具/真机、Ubuntu 24.04 或规定负载性能验收。
- 不引入 Celery、新消息队列或第二套交易事件通道。
