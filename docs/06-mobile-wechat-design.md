# 移动H5与微信小程序联合设计

2026-11-09 · Web 与原生小程序实施基线 `17f5b91`。本页记录共用交易规则、分端交互和设备验收条件。

## 1. 客户端范围与边界

从本版起，需求、接口和验收必须同步考虑PC商城、移动H5、买家微信小程序。内部运营后台以PC为主要工作环境，窄屏支持查单、库存查询及必要履约；不把完整管理后台搬入买家小程序。

| 维度 | PC商城 | 移动H5 | 微信小程序 |
| --- | --- | --- | --- |
| 导航 | 顶部搜索/分类/用户中心 | 首页、分类、购物车、我的；详情页购买栏 | 根页面TabBar；详情/结算采用页面栈；预留原生胶囊区域 |
| 商品 | 图文双栏 | 单列图片、底部规格面板 | 单列图片、规格面板，单独适配原生组件行为 |
| 登录 | 商城账号 | 商城账号；登录后恢复原操作 | 商城账号密码建立 mini 会话；微信身份换证及显式绑定待接入 |
| 地址 | 站内地址管理 | 站内地址管理 | 站内地址 + 可用时的微信地址选择；失败可手填 |
| 通知 | 站内消息 | 站内消息 | 站内消息兜底 + 用户主动选择的订单订阅提醒 |
| 分享 | URL | 浏览器能力适配，不保证所有浏览器都支持同一方式 | 商品分享路径；从分享直接进入也能正常返回 |
| 生命周期 | 刷新恢复 | 浏览器返回/刷新/后台恢复 | 页面与应用切后台/恢复/冷启动；不能依赖内存状态永久存在 |
| 支付 | 模拟 | 模拟 | 模拟；不调用真实微信支付 |

共用商品、SKU、价格、库存、订单、优惠券、权限和错误码。不得在小程序内复制一套交易计算逻辑。Vue网页组件不视为可直接运行的小程序组件。

## 2. 视觉与交互规范

继续沿用V2暖白、深松绿、浅鼠尾草绿。手机正文以14–16px为设计基准，输入控件16px，主要触控区域至少44×44设计像素；数字与金额对齐。页面按320/375/390/430逻辑宽度设计，不通过等比例缩小桌面页适配。

- 详情页操作栏：购物车/客服为辅助，购买为主要动作；不能覆盖最后一段内容。
- 规格面板：颜色、容量、库存、数量、金额与主按钮在一个任务范围内；取消不丢已选规格。
- 一级页面才显示主导航；结算页不与TabBar竞争空间。
- 小程序优先使用原生导航；如定制导航，按真实设备胶囊/状态栏信息布局，不硬编码设备高度。
- 预留底部安全区；软键盘弹出时确保正在填写的字段和错误提示可见，不能只验收静态截图。
- 禁止仅通过颜色表达错误，按钮有动词文案，取消/失败/空态均有下一步。
- PC后台窄屏列表转信息卡片，编辑表单分段；手机上的批量高风险操作可限制为只读。

## 3. 身份与账号设计

浏览、搜索和选规格不要求登录。下单、查看本人订单和发送个人客服消息时再进入登录；保留商品、数量、券选择和登录后的目标页面。未同意必要服务说明时不建立账号会话，但仍可浏览；正式政策文案须匹配实际数据范围。

微信身份登录、手机号获取、头像昵称、地址、消息订阅是不同能力，不做一次全量强制授权。手机号不作为浏览前置条件；地址电话按履约需要收集。拒绝非必要能力不阻断购买。

统一使用内部mall_user_id。外部身份映射保存provider、appid、外部标识与内部用户关系，唯一约束由后端保证。不得根据昵称或头像合并账号；如需关联已有手机号账号，必须通过已有账号验证与明确绑定操作。解绑、重复绑定、账号停用分别设计错误出口。可用的跨应用身份标识不作为始终存在的前提。

H5/PC采用浏览器会话方案：短期access内存、refresh HttpOnly/Secure Cookie，并完成CSRF与来源校验。小程序单独设计会话存储与刷新适配，不能假定浏览器Cookie协议直接通用；使用短期access、可轮换/撤销的客户端会话，退出时清理本端凭据。平台临时凭据由后端校验；平台密钥与会话密钥不传给前端。微信平台登录态与商城JWT有效性分别判断。

Web Cookie 与小程序 JSON 刷新协议已分别实现。外部微信身份映射、换证与绑定仍属于接入设计。

## 4. 地址、通知、分享

地址：微信地址选择成功后先展示确认，转换为商城字段再保存；取消、权限拒绝、能力不可用都保留手动填写入口。不要在页面加载时自动索取地址或地理位置。购物订单保存地址快照，后续改地址不影响已提交订单。

消息：订单创建/支付后提供明确的提醒入口，由用户点击触发平台申请；区分同意、拒绝、失败、不可用，拒绝后不循环打扰。订阅偏好不等于永久授权或送达保证；服务端按实际能力、模板、授权结果投递，订单页和站内消息始终可用。不同订阅机制与账号权限待接入时按官方控制台确认，不在本稿锁定过时的API或费用。

分享：仅携带商品标识和允许的活动参数，不含token、手机号、地址或订单详情。分享进入属于冷启动入口，商品不存在/下架要有替代导航；返回操作不能依赖必然存在上一页。H5根据浏览器能力提供可用分享方式，小程序按平台分享入口实现。

## 5. 交易与恢复

三端共用价格试算与订单状态机；金额以服务端为准，十进制字符串传输。下单幂等键绑定内部账号和业务操作，不能以端类型绕过唯一约束；多端同时抢同一券或库存必须有相同事务保护。

页面恢复流程：恢复必要的非敏感选择 → 检查商城会话 → 重新查询订单/商品最新状态 → 展示实际结果。UI倒计时不能决定订单是否已关闭。

- 提交结果未知：保存本次提交标识，查询同一操作，不创建新幂等键重试。
- 支付离开/返回：重新查询订单；前端回调和页面跳转不能独自决定支付成功。
- 登录过期：恢复登录后继续原订单/结算，不能清空购物选择。
- 商品价格变化：重新试算并要求确认；库存不足或下架明确阻断提交。
- 弱网：允许浏览已缓存的非敏感内容；不得离线确认下单、支付、库存或券核销。
- 不把完整地址、手机号、token放入分享参数、日志或跨端同步数据。

## 6. 开发架构约束

Web继续采用Vue3，后端Django5.2/DRF、MariaDB、Redis及Ubuntu24.04直接部署保持不变。小程序采用独立原生工程，页面与适配层分别位于 mini/pages 和 mini/utils。

建议划分公共业务契约与平台适配层：身份、存储、导航、分享、地址、消息、网络状态分别适配。共享的是字段契约、业务规则和测试数据；DOM、浏览器存储与原生组件不进入公共业务模块。

待接入的目标能力有微信平台凭据换商城会话及外部身份绑定/解绑。订阅授权结果登记接口已存在，平台申请与实际发送仍待实现。商品/订单/地址/券沿用已有业务API。所有接口仍验证身份与对象所有权，client_type只用于诊断，不能作为权限依据。

端版本与接口版本分离。服务端升级要兼容旧小程序客户端，使用可选新增字段、能力判断和必要的最低版本提示。媒体域名、请求域名、TLS、AppID、隐私声明、类目及消息模板以实际平台配置核验。

## 9. 原生实现登记（2026-11-09）

X01已决策采用无跨端依赖的原生微信小程序，源码位于 `mini/`。选择依据是现有后端与Vue Web可共用API而不必共用DOM，原生导航、分享、存储、前后台恢复和平台能力需要独立适配；没有引入新的跨端运行时或容器。`project.config.json` 的真实AppID留空，开发者工具、体验版和真机未执行。

分端商城会话使用 `auth/mini/login/`、`refresh/`、`logout/` 与 `AuthSession.ClientKind.MINI`，refresh存于小程序本地并轮换，Web Cookie refresh与mini JSON refresh不能跨协议。该登录是商城账号会话，不是微信身份登录；官方登录文档已核对临时code一次使用和服务端 `auth.code2Session`/`session_key` 边界。当前没有AppID/AppSecret，未实现微信平台proof换会话，也不按昵称头像合并账号。

原生页面已覆盖CMS首页、商品/规格/分享、游客购物车登录合并、地址、选券试算下单、订单恢复与模拟支付、评价、消息、受限内容块及客服。订阅与微信地址按钮仅提示未配置，手填地址与站内消息可用。Node测试覆盖并发401一次刷新、写请求不自动重放、退出清理和游客合并原键重试。上述是实现与静态/单元测试证据，不是开发者工具编译、微信API、体验版或iOS/Android真机结果。


## 10. 原生页面复验与设备走查

| 场景 | 实现及自动证据 | 设备上复核什么 |
